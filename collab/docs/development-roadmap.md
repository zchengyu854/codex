## 1. 目标与范围

交付一个能在 macOS 终端中用于真实 Git 项目的多模型协作工具：操作者配置一个主控和最多三个工作 Agent，派发需求、查看进度与历史产物、审查差异，执行项目自身检查后集成到协作分支。

继续使用 Rust core + TUI、SQLite、本地 JSON 行协议、每任务独立执行会话和 Git worktree。沿用已确定的单终端多窗格路线。当前分发目标为 macOS；跨平台需要单独验收。

本计划从已完成的阶段 7 继续编号。阶段 1–7 文档保留各自当时的设计与实测记录；评估当前状态优先看 README、本文和各阶段最终汇总，避免把历史文档里的“未接入”当成现状。

## 4. 阶段 8：真实代码项目验收

### 8-1 可复现的代码项目与离线剧本

交付：一个独立 Git 测试项目及场景驱动脚本，复用现有 Host、任务派发、事件观察和脱敏方式。项目可采用 Python 标准库与 unittest，避免为了验收引入包管理和下载依赖。

剧本：

1. 初始化含可运行代码及测试的干净仓库，基线检查通过。
2. 主控委派两个独立工作任务，分别修改不同实现文件及各自测试；每份候选单独集成时都能通过项目检查。
3. 主控创建第三个工作任务，依赖前两个任务，完成使用两项变更的功能及测试。前两个任务集成前，第三个保持 queued。
4. 主控审查指定候选提交，宿主依次集成，并在最新集成头执行项目自身的非空测试集。

验收：本地模拟上游下可重复运行；测试既有预期通过用例，也有能识别错误实现的用例。证据记录任务来源、Agent、依赖、候选提交、集成前后 head、实际验证命令与退出码，源仓库保持不变。

### 8-2 失败与冲突恢复

在同一测试项目中分别验证：

- **测试失败**：候选导致真实测试失败，集成分支不前进；失败原因和候选内容可查看。保留 failed 工作区供核查；8-2 已将 abortIntegration 扩展为仅恢复当前归属的 conflict/failed/interrupted 候选，不能作为任意工作区清理接口。
- **同行冲突**：两个同基线任务修改同一实现位置；第二次集成停止于 conflict，显式放弃后工作区干净、已集成内容与候选提交保留。
- **返工**：新建带原任务引用的明确修复任务，在当前集成头上完成修改，再审查新提交。不能直接重试未改变的冲突候选并宣称已恢复。
- **中断**：任务取消和宿主重启后，已提交产物不丢失，任务状态可解释；有外部副作用的操作不自动重放。

复用现有失败处理；只有验收发现缺口时才增加最小恢复操作，并写清会清除哪些工作区修改。任何清理都不得删除源仓库或其它任务产物。

验收：每个失败点都有本地可重复回归，证据证明分支及产物状态，不依赖模型“已完成”的自述。

### 8-3 真实模型验收与结论

对 8-1 的完整协作剧本和 8-2 的冲突返工链路运行真实模型；故意注入的失败矩阵优先在本地验证，不要求每种错误都付费制造一次。

- 使用合成项目，不默认发送用户业务仓库；沿用 Keychain、端点脱敏和逐条审批。
- 记录协议、模型、任务数量、请求/重试、用量（上游提供时）、耗时和审批次数；缺少单价时不估造金额。
- 同一凭证限流时记录等待与失败，不通过无限重跑掩盖问题。宿主并发与上游请求并发分别描述。
- 真实运行未通过时保留失败证据，定位产品问题或环境限制；未执行的场景不能标通过。

预期交付：`docs/stage-8-plan.md`、场景脚本/fixture、`evidence/stage-8-*.json`、派生日志和汇总。验收必须包含真实测试命令成功、依赖门时序成立、至少一次真实冲突返工成功、源仓库干净。

## 5. 阶段 9：任务历史与返工操作

### 9-1 历史任务选择

复用 `task/list` 添加会话任务列表入口。最小显示：任务短 id、Agent、目标摘要、任务状态、集成状态和依赖；能选择历史任务后查看详情与结果。

选中的 taskId 是后续操作的唯一目标。新任务到达、自动刷新或同一 Agent 继续工作时，不能把已打开的旧任务悄悄替换为最新任务。切换会话时清除选择，旧会话响应不得更新新会话界面。

验收：同一 Agent 连续完成两个任务后，仍能查看第一份结果和差异；会话切换与运行中刷新不串任务。列表支持键盘操作、滚动和明确的当前选择。

### 9-2 对历史产物执行操作

从所选任务进入审查/集成、冲突放弃、取消运行中任务，沿用宿主的状态检查和 reviewedCommit 校验。显示完整目标任务信息，防止把操作应用到同窗格的另一个任务。

提供“基于此任务新建返工任务”：预填原任务 id、原目标及验收说明，用户可编辑后显式派发；原任务状态和结果不覆盖。复用 task/create，不加入自动重试或新的任务状态。

验收：旧的 completed/pending 任务能集成；旧冲突可放弃；返工生成新 taskId；已集成或运行中任务不能走错误的集成路径。保留既有快速派发、结果查看与按键行为的回归覆盖。

预期交付：`docs/stage-9-plan.md`、TUI 操作说明、针对 taskId 路由的测试与 pty 证据。

## 7. 阶段 11：协议与长会话验收

### 11-1 Responses 与混合配置

在有可用凭证及明确运行范围时，复用阶段 8 项目验证真实 Responses 的公开文本流、工具调用、用量、取消与集成。随后验证同一会话中主控/worker 使用不同协议的协作，避免把“能连通”当成完整协作通过。

对两种协议分别记录支持范围；缺少真实 Responses 服务商时保留“仅本地覆盖”，不阻塞已验证的 chat_completions 发布。图片、内置搜索、结构化输出不因此自动纳入。

### 11-2 长会话与上下文压缩

构造有用户约束、正式决策、任务依赖与已集成产物的较长会话，在明确预算下触发手动或主控显式压缩。复用 expectedRevision 与现有保留规则，先用本地场景验证，再进行一次有界的真实续作。

验收：过期 revision 被拒绝；压缩后权威约束、依赖、任务状态和审计历史保留；后续模型请求确实消费压缩后的上下文并完成满足原约束的代码任务。超出预算时明确暂停，不能静默丢弃记录。自动压缩、长期记忆和语义检索不在本段范围。

预期交付：`docs/stage-11-plan.md`、协议/压缩场景、真实与模拟证据分栏的汇总。

## 8. 暂缓模块及启动条件

| 模块 | 启动条件 | 需要覆盖的边界 |
| --- | --- | --- |
| Windows / Linux | 有明确目标平台和可运行验收环境 | 系统凭证库、进程组/取消、路径、终端、Git worktree、安装；不能只替换 Keychain 就宣称跨平台 |
| 任务级预批准 | 非提交类操作反复审批，实际妨碍任务完成 | 操作者选择、命令范围、过期/撤销、审计；默认仍逐条审批 |
| 多模态与协议扩展 | 有具体图片/结构化输出等工作流 | 按协议独立定义支持范围、工具与附件处理，不能静默忽略不支持字段 |
| 成本预算控制 | 已有用量数据表明需要额度保护 | 可靠的用量来源、明确的模型单价或 token 上限；未知费用不得显示为 0 |
| 会话归档与清理 | 多项目持续使用产生可量化磁盘负担 | 预览占用、候选提交保留、恢复路径、显式确认；不自动清除活跃工作区 |

图形桌面、多机共享宿主、远程控制、任意数量 Agent、自动解决冲突均不在本计划的交付承诺中。
